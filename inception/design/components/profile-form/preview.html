Profile form

The profile half of SCR-005 (REQ-007, REQ-008). One Save for all four editable fields — the designer's call, 2026-08-28 — so this component owns an unsaved-changes state and a multi-error state that per-field editing would not have. The identity block above the divider is read-only: REQ-007 names exactly four editable fields and the name, email and rating are not among them.

Save is disabled until something differs, so the button itself tells the employee whether they have unsaved work. The rating carries its numeral and its count — a bare row of stars would put the whole meaning in a shape, and a 5.0 from one session would read as a track record.

ST-02 — Loading

Labels are real, values are skeletons: the label text is known before the data arrives, so the form does not re-flow when values land. The region is aria-busy="true".

ST-05 — Could not load (whole screen)

⚠ We couldn't load your profile.

One error for the screen, because the screen loads in one request. The app header stays above this and stays usable — the employee is never trapped on a page they cannot leave.

Leaving the screen in this state asks for confirmation and names what is at stake. Cancel reverts every field to its loaded value with no network call, and is deliberately not confirm-guarded while Save is one click away.

ST-07 — Saving

Fields go read-only so an edit made mid-flight cannot be silently discarded. The skills cards below this one stay fully interactive — the two save paths on this screen are independent.
