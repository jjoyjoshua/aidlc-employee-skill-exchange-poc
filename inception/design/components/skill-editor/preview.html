Skill editor

The dialog behind Add a skill and Edit on SCR-005 (REQ-009, REQ-010, REQ-011). A dialog rather than an inline form because adding a skill is three coupled choices — which list, which catalog skill, which proficiency — that are only valid together, and the catalog needs a search field. The same dialog is reused for editing. On mobile it becomes a full-height sheet with its actions pinned in view, so the primary button never sits behind the keyboard.

ST-13 — Add a skill

Add a skill

Is this something you teach, or something you want to learn?

ℹ Colleagues will be able to find and book you for this straight away.

ℹ Pick from the list. The skill catalog is maintained centrally.

Proficiency

Add skill stays disabled until both a catalog skill and a proficiency are chosen — no proficiency is pre-selected, because a default here would be the system guessing how good someone is at something. The consequence panel appears only while "I can teach this" is selected: REQ-013 and BR-001.1 make that choice public immediately, with no approval step, and that is the most surprising thing this screen does. The employee meets it before it happens rather than discovering it from a booking request. Levels are spelled out, never dots or colours.

ST-14 — That skill isn't in the catalog

Add a skill

No skill matches “kubernetes”. ℹ The skill catalog is maintained centrally, so it can't be added from here. TBD (OQ-E5) — how an employee asks for a new catalog entry, and the exact wording, is not yet decided. Owner: BA + IT.

This state matters more than it looks. RISK-001 in the BRD is precisely this moment — the point where an employee with a skill the organization wants either gets a route or gives up. The BRD names a "lightweight request-a-new-skill path to IT" as the mitigation, but no requirement creates one and BRD §8 rules out an in-app editor. The dashed placeholder stays on screen until someone owns the answer; free text is never accepted as a skill, because trainer search matches on catalog entries.

ST-15 — You've already listed that

Add a skill

⚠ You already teach Excel at Expert level.

A dead end with a way out: the note offers the edit the employee probably wanted. The same skill in the other list is not a duplicate and is not blocked — REQ-009 says a skill may be listed "to teach and/or to learn", so someone may teach Excel and be learning Excel at once. Whether that literal reading is what was intended is OQ-E4, and it belongs to the BA.

Proficiency

ST-19 — Editing a listed skill

Edit skill

● Excel

ℹ To list a different skill, remove this one and add the other.

Is this something you teach, or something you want to learn?
Proficiency

The skill itself is fixed text, not a search field: changing which skill it is would be removing one and adding another, not an edit. Save changes is disabled until something actually differs, the same rule the profile form uses. Switching teach ↔ learn here moves the chip between cards on save; if that would collide with an entry already in the target list, ST-15's note applies.

ST-20 — Removing a skill

Remove Excel from the skills you teach?

⚠ Colleagues will no longer find you for this skill.

Focus starts on Cancel, not Remove, so a stray Enter cannot delete a skill. Removal is confirmed and a proficiency change is not, because removal cannot be undone from this screen and, for a teachable skill, changes who can reach the employee. While removing, both buttons disable and Remove shows a spinner.

ST-20 — Removal refused (conflict C-1's working default)

Excel can't be removed yet

⚠ You have 1 upcoming session and 2 pending requests for Excel. Cancel or complete these before removing the skill.
Placeholder — conflict C-1. REQ-011 lets an employee remove a listed skill unconditionally; REQ-015, REQ-017 and REQ-021 let requests and confirmed sessions exist against it. Nothing says which wins. This draws the conservative reading so the frames can be built; the decision is the BA's.

Shown so the reviewer can see the shape of the conservative default, not because it is settled. If the BA rules the other way, this becomes an ordinary confirm carrying a warning about the sessions it will affect — same dialog, different copy and a different primary action.
